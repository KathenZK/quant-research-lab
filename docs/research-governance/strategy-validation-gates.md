# Strategy Validation Gates / 策略验证门禁

本文件定义本仓库从研究版本推进到 runner / dry-run / live 前需要补齐的验证证据。它服务于现有状态机，不引入新状态；状态词仍以 [strategy-status-glossary.md](strategy-status-glossary.md) 为唯一来源。

## 2026-09-03 修订摘要

- **硬门禁后移**：门禁 0–4 与 live-executable 审计从 `registered -> live spec` 移到 `dry-run -> live`，与线上开平仓对账并列。
- **registered 可直达 dry-run**：`registered -> live spec` 与 `registered -> dry-run` 只要求身份冻结、runner 可复现、交接规格字段齐备；dry-run 另需用户授权、对拍或 smoke、以及 `runner-tracking/`。
- **live spec 可选**：不再是 dry-run 的必经前置。现有 dry-run 不因本修订自动降级。

本规范是仓库内部工作流说明，不是对外复现规格。门禁报告应沉淀在对应策略家族目录下，core ledger 只保存状态、结论和证据链接，不承载完整实验输出。

## 2026-08-06 修订摘要

- **相位改为检查项**：相位 / K 线切分边界不再是 promotion 硬门禁；结果差、未达到参考阈值或缺少更细粒度数据，均不得单独构成 `not live-ready` blocker。
- **保留报告义务**：数据可得且成本合理时仍应检查并如实披露原生/伪相位差异，用于识别边界依赖、评估收益可信度和安排前瞻观察；不得把未检查写成通过。
- 研究侧硬门禁为 `0/1/2`，上线前硬门禁为 `3/4` + live-executable；相位作为非强制检查项 5 进入 promotion review 附录。

## 2026-07-15 修订摘要（历史口径）

- **删除**原门禁 5（统计显著性 / PSR·DSR·MinTRL）与原门禁 6（启动时间敏感性）：前者在本仓库常因缺少 `trials.csv` 导致 `N` 不可信，后者与 OOS、交易 bootstrap 高度重叠。
- **当时保留并重编号**：原门禁 7（相位）→ 门禁 5；该硬门禁口径已被 2026-08-06 修订取代。
- **优化**：消融只测有效旋钮；OOS 以独立交易数为主；MC 默认必做子集；压力测试区分执行完整性与绩效报告；相位阈值与扫描成本下调。
- **简化状态机**：`audit` 不再是主状态；登记时只记录门禁缺口，准备写 `live spec` 时一次性完成硬门禁、检查项与 live-executable promotion review。
- 历史报告中的「Gate 5/6/7」编号仍按当时口径理解，不批量改写；新 promotion 一律按本文。

## 适用原则

- “登记 / 冻结 Vx”只完成 `explore -> registered` 的身份固定，不是 promotion；“promote”必须明确目标状态，不得与登记混用。
- 门禁用于状态迁移：回测结果再好，也不能绕过 `dry-run -> live` 的硬门禁、live-executable 审计与线上开平仓对账。`registered -> dry-run` 合法直达；`live spec` 为可选中间态。
- 阈值是默认口径：默认按本文执行；若因策略频率、样本长度、市场结构或数据可得性需要偏离，报告必须说明原因、替代口径和影响，并在家族 `decision-log.md` 记录。
- 缺数据不是通过：硬门禁缺少必要数据时记录为未完成 blocker；相位检查缺少更细粒度数据时记录为“未检查 / 数据不足”，但不单独阻止 promotion。
- 证据按现有目录落地：Markdown 报告进 `diagnostics/`、`ablations/` 或 `notes/`；脚本进 `scripts/`；需保留的 JSON/CSV/图表进 `artifacts/`；状态迁移结论进 `decision-log.md`；core ledger 放紧凑链接。
- 现有 dry-run 或历史版本不因本文件自动降级；但任何后续升 `live` 或重新 promotion，都应按本文补齐缺口。
- PSR/DSR/MinTRL、起跑点全扫等可作为**可选诊断**写入报告，不再构成硬性 blocker。

## 状态迁移映射

| 迁移 | 需要核验的门禁 | 结果落点 |
| --- | --- | --- |
| `explore -> registered` | 不新增门禁；只固定版本身份、参数和证据链接 | core ledger |
| `registered -> live spec` | 身份冻结；参数/状态机可被 runner 复现；交接规格必备字段齐备。不要求硬门禁 0–4 或 live-executable 审计 | live-specs / decision log |
| `registered -> dry-run` | 用户显式授权；runner 实现完成；指标对拍或 smoke 通过；同一变更建立 `runner-tracking/`；身份冻结、runner 可复现、交接规格字段齐备。不要求硬门禁 0–4 或 live-executable 审计 | live-specs / runner-tracking |
| `live spec -> dry-run` | 同 `registered -> dry-run`（尚未满足的项在本步补齐） | live-specs / runner-tracking |
| `dry-run -> live` | 硬门禁 0–4 + live-executable 审计，并记录相位检查项 5（可得时）；runner 观察证据、已完成的线上开平仓逐笔对账（无未解决重大偏差）、运维风控、重启恢复、missing-bar fail-closed、kill switch；离线 replay/parity 不可替代线上对账；相位结果不得单独否决 | ablations / diagnostics / runner-tracking / artifacts / decision log |

## 门禁 0：超额收益基准

目的：确认策略不是把市场 beta 伪装成 alpha。

默认口径：

- 单标的方向/择时策略：策略收益减去同标的 buy-and-hold（同成本假设下报告）。
- 篮子或组合策略：策略收益减去等权持有对应标的篮子。
- 报告超额收益、样本窗口、成本假设；优先给 IR 或超额收益 bootstrap 置信区间之一即可，不必两套都做。

允许偏离：

- 短持仓、均值回归、做市、套利或净空头偏置策略：可用 flat/cash、funding-adjusted hold 或明确声明的替代基准，并写明理由。
- 有效交易过少（例如全样本独立成交 < 30 笔）时，不把「IR 不显著」单独写成硬失败；应结合门禁 2 的样本外稳定性判断，并在报告中标明样本不足。

判定：

- 在约定基准下，全样本超额收益不显著优于 0、且近期主要切片也无稳定超额时，不推进 promotion。
- 对明确非方向策略，写明基准不适用与替代检验即可，不机械套用 buy-and-hold。

## 门禁 1：消融实验

目的：确认入场、关键过滤、退出族和风控部件不是噪声拟合或死代码。

默认口径：

- 只消融**实际接线且会影响成交序列**的部件；已删除、未接线、被 binary 忽略的参数不进清单。
- 优先三类：主入场条件、主过滤（可按「过滤束」一次关闭）、主退出族（TP/SL/timeout/indicator exit 中至少覆盖会改变路径的一类）。微参数邻域扫描留给门禁 3 的 `mc4`，不必在消融里逐个拨。
- 每个消融变体必须验证成交笔数或成交序列相对 full 有变化；完全一致则先排查旋钮是否无效。
- 报告各变体相对 full 的 PnL、MDD、胜率、Sharpe、trade count 差异即可，不要求穷尽交叉消融。

判定：

- Alpha 或过滤部件应有可解释正贡献，或合理解释为必要风控/执行约束。
- 风控部件可以牺牲收益，但必须证明降低尾部风险、回撤、裸仓风险或执行风险。
- 无贡献且无风险解释的部件应删除，或记为重构 blocker（不必因此否定整条策略的其他门禁）。

## 门禁 2：OOS / CPCV

目的：检查策略是否只在单一历史切片或调参窗口上有效。

默认口径：

- 优先 CPCV 或滚动 OOS；推荐基线 `IS 60d + gap 10d + OOS 30d`，可按交易频率调整窗口长度。
- **以有效独立交易数与 regime 覆盖为主，不以窗口组数凑数**：样本足够时目标约 15+ 组；短历史或低频策略可用更少组，但须报告每组 OOS 成交笔数与零交易窗口数。
- 报告每个 OOS 窗口的收益、Sharpe、MDD、trade count，以及 OOS 正收益占比。

允许偏离：

- 低频、事件型或数据历史短：可用更长 OOS、walk-forward、留后段 holdout 或横截面 OOS。
- 与仓库默认 recent slices（`1d/7d/1m/3m/6m/1y`）互补时，slices 可作审计附录，但**不能单独替代**结构化 OOS/CPCV，除非报告说明为何窗口法不可行。

判定：

- OOS 正收益占比接近抛硬币、多个主要 regime 崩塌、或多数 OOS 窗口有效成交不足以判断时，不推进 promotion。
- 不要仅因「未凑满 30 组」机械失败；也不要在窗口内几乎无成交时机械通过。

## 门禁 3：Monte Carlo 稳健性

目的：检查交易分布与参数邻域在轻微扰动后是否仍稳定。

默认必做：

- `mc3` 交易抽样：bootstrap 历史交易，报告 PnL、MDD、胜率、Sharpe 的分位数。
- `mc4` 参数扰动：在冻结参数邻域扫描，判断是高原还是尖峰；离散规则改为邻近可行规则扰动。

按需加做：

- `mc1` K 线扰动：信号对单 bar 噪声极敏感、或依赖精细 OHLC 路径时再做。
- `mc2` 交易重排：存在复利 sizing、连续亏损停机、锁仓/冷却等路径依赖时再做；无路径依赖时可与 `mc3` 合并表述为「交易分布稳健性」，不必单独跑重排。

判定：

- 报告分布与分位数（至少中位与约 5%–10% 尾部）；若邻域轻微扰动即大面积转亏，或参数只在针尖上有效，不推进 `live`。
- 不要求四套 MC 全部通过才算过门；缺做的子集须在报告写明「不适用/未做及原因」。

## 门禁 4：压力测试

目的：确认极端行情与执行异常不会造成裸仓、爆仓或保护单失效。

硬性（必须通过）：

- 执行完整性：滑点放大、成交延迟、拒单、断流后恢复、跳空穿越保护价时的成交假设；报告是否出现裸仓、仓位不一致、保护单无效、断流后错误继续下单。
- 至少覆盖策略样本内 1–2 段已知极端或高波动区间（暴跌/暴涨/闪崩/流动性骤降之一即可），检查保护单与仓位状态，而不是要求「每个宏观事件日都重跑全套绩效」。

报告项（记录即可，不单独因绩效变差一票否决）：

- 极端区间或模拟压力下的 PnL、MDD、单笔最大亏损；与基线对比说明即可。

判定：

- 出现无法解释的裸仓、爆仓路径、保护单无效、断流后错误下单时，不推进 `live`。
- 压力下收益变差或回撤变大，本身不是失败；失败标准是**执行与风控合同被打破**。

## 检查项 5：相位 / K 线切分边界（非强制）

目的：检查策略是否只在交易所原生 K 线边界上好看，并量化边界依赖；本项用于解释证据强度，不单独决定 promotion。

默认口径：

- 对策略用到的主周期逐周期扫描；一次只扰动一个周期，其余保持原生。辅助周期（如仅作 regime 的更高周期）可只扫 `{0}` 与一个半周期偏移（如 1h 的 `{0, 30}`），不必与主周期同等密度。
- 15m 主周期：优先用真实 1m（或更细）重聚合 `{0, 5, 10}` 分钟相位；若已有证据显示边界依赖，再扩展到 `{0, 3, 5, 6, 9, 10, 12}`。
- 30m 主周期：优先 `{0, 10, 20}`；1h 及以上：优先 `{0, 30}`。
- 每个相位抽样多个起跑点以覆盖不同 regime；默认每相位约 8–12 个起跑点即可（不再要求为凑启动时间门禁而做逐 bar 全扫）。
- 聚合必须来自真实更细粒度 K 线或逐笔数据，不能从原生周期插值伪造偏移 bar。

参考读数（诊断基准，不是通过阈值）：

- 报告各相位收益中位数、正收益相位占比、原生相位相对中位数的偏离、MDD 分布与有效交易数。
- 可继续参考：非原生相位收益中位数 / 原生相位收益、非原生相位 MDD 中位数 / 原生相位 MDD、跨相位收益 CV；原 `40% / 2.0x / 0.75` 仅作历史比较线，不再作准入标准。
- 原生相位明显优于伪相位时，应披露收益可能依赖交易所原生收线边界，并优先使用冻结后的前瞻观察、跨年份/月份或邻近相位结果校准可信度。

结果处理：

- 若策略明确捕捉原生收线边界订单流或结算节奏，可按「时钟边界 alpha」补充举证：原生边界附近存在事件效应、信号只在收线后确认、跨月份/年份仍有效、临近伪边界不等效、扣成本后仍有优势。
- 相位崩塌、参考线未达到或相位数据不可得，只能降低证据置信度、增加前瞻观察要求或记录风险提示，**不得单独写成 `not live-ready` blocker**。
- 若相位检查暴露的是 lookahead、错误 K 线聚合、不可用数据或真实 runner 无法复现原生边界，则应按对应的数据质量、执行完整性或 runner parity 硬门禁处理；blocker 来源不是相位绩效本身。

## 报告最小模板

每份门禁报告至少包含：

- 策略家族、版本、状态迁移目标。
- 数据来源、市场、symbol、timeframe、UTC 区间、成本模型和 closed-bar 口径。
- 本次覆盖的门禁、默认口径、是否偏离、偏离原因。
- 关键指标、分布或切片结果。
- 硬门禁写通过 / 未通过 / 数据不足；相位检查项写已检查 / 未检查，并说明对证据置信度的影响，不给出单独准入裁决。
- 后续状态建议：停留 `registered`、进入 `live spec` 或 `dry-run`、申请 `live`、或保持 `not promoted / not live-ready`。
- 证据链接：脚本、artifacts、相关 core ledger 和 decision log。
