# 含资金费为什么比不计资金费赚得多：2026-09-10 复核

## 结论

**在原账户规则和已保存数据下，含资金费收益更高确实能复现；本轮没有发现收付方向、重复记账、数量倍率或复利错误。大额负资金费也有官方原文支持，不只是一个程序算出来的结果。**

但完整历史来源复查没有完成，不能把原来的 **+10,085.43%** 称为已验证的精确实盘净收益。下面明确区分全部完成的账目检查、部分完成的官方来源检查，以及仍未模拟的交易条件。本轮不改 Top10、不删亏损月份、不调退出或风险参数；旧结果、输入和代码均保留。

## 2. 独立重记全部账户：没有发现账目错误

新算法不用旧会计计算：每段价格盈亏直接算“固定数量 ×（退出价－进入价）”，资金费现金另算，换仓成本独立求解。这样不会把资金结算时标记价的变化再算成第二份价格利润。

- 四条账户各 2,390 个净值点、1,393 笔换仓成交全部匹配；三条含费账户各 97,421 笔资金现金逐笔匹配。
- 最大净值差 **0.0000001695 USDT**，符合事先沿用的浮点误差要求。数量字段按相对与绝对联合误差检查，不声称所有大数量字段绝对误差都小于百万分之一。
- 97,421 笔事件都只归入一个实际持仓区间，没有重复事件或持仓外入账。
- 正费率 70,353 笔，多头支付；负费率 26,287 笔，多头收取；零费率 781 笔。没有算反方向。
- 每月按同样一块本金计算，两个账户的价格收益因子相同；含费账户增加的部分恰好是当月资金现金除以月初本金，再扣各自换仓成本。

含费账户一共收到 **8,893,994.47**、付出 **2,023,054.97 USDT**。差额不能全部说成“选 Top10 多赚了这么多趋势利润”。

另外固定使用不计资金费账户原有的每月持币数量，不让资金费影响后续仓位，重新计算的资金费为：收到 **3,537,576.47**、付出 **1,752,920.60**、净收 **1,784,655.86 USDT**。这说明直接资金收入本身仍明显为正，不是全靠复利算法制造。

这只是拆分账目，**不是一条新的可执行、自给资金的策略**。不应把“不计费账户期末再加这笔现金”当作第三条实盘收益回测。真正含费模型每月会重新分配本金，因此它的后续现金额和价格盈亏都会不同。

## 5. 官方来源查到了哪里，哪里还没查全

本轮按全部 760 个持仓窗口安排查询，不只挑已知负费率月份。今日成功获得 **134** 个完整窗口、12,240 笔；复用昨日请求窗口完全相同的 **4** 个官方原文、2,462 笔。138 个完整查询窗口内，未发现多记、漏记、费率或类型冲突。时间差最大 45 毫秒，唯一映射后费率差为零。

查询途中官方接口返回 HTTP 403，采集已停止。今日共保留 189 份请求回执，其中 134 份成功、55 份 403；首个 403 后仍有后续窗口请求，不能表述为首个拒绝就即时停机。没有重试被拒请求、切换 IP 或路径绕过限制。未返回及未请求部分不按零资金费处理。

随后只读项目里此前保存的官方原文和原清单哈希，不继续发网络。合并目前可追溯的明确类型 API 证据，共 **16,211 / 97,421** 笔匹配，全部明确为 Regular；仍有 **81,210** 笔没有得到本轮 API 原文复核。加上无类型、无 mark 的官方月档旁证，费率获得本轮原文支持的事件并集为 **16,584** 笔，但月档旁证不能冒充原生类型或完整结算日历证明。

## 6. 标记价检查与真实结算价的影响

全部 97,421 笔旧账户使用的标记价都从原始文件重新解析核对：1,493 个实际使用的原文哈希一致，761 个 ZIP 另验官方 CHECKSUM；独立检查 33,354,668 条分钟时间和所用 OHLC 字段，无错列或时间单位差异。含 `1000` 数量前缀的合约另作检查，没有 100 倍、1000 倍放大错误。与同日实际成交区间比较也没有 2 倍异常；日范围检查不是同一时点的基差或可成交证明。

可取得原生结算标记价的共有 **3,695** 笔，来自 HOME、LAB、H、MYX、AIA、PIPPIN、RIVER 七个资产。其中 1,233 笔原模型已经用原生值，本轮另外核到 2,462 笔可替换原分钟代理。
