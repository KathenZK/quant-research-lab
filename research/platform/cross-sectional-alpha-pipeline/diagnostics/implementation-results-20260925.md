## 二、相对强弱错误是怎么修的

原实现把多个币放在一个表里直接计算前后行收益。当 A 的末价为110、紧接着 B 的首价为1000，基准不变时，B 的第一条“收益”会被算成：

`1000 / 110 − 1 = 8.090909`，即 **+809.09%**。

这不是 B 的历史收益，只是把两个不同资产接在了一起。修复后 B 第一条没有自己的前值，结果保持缺失；B 第二条仍为1000时收益为0。资产、交易所、市场类型、周期和连续研究段之间均不再串算。

相对强弱定义保持为“资产过去 n 根收益减基准过去 n 根收益”，默认 n=24，使用小数收益差；值高只表示过去更强，不自动表示未来能赚钱。因子不向前填补缺失。输入带时间列时，重复与段内倒序直接拒绝。

默认24根因子缓存身份由 `0516390680466515` 变为 `661ad581d7ffe094`，因此旧缓存不会自动冒充修复后的计算；旧源码快照、旧缓存和旧研究输出均保留。

静态调用审查覆盖当前 Python 源文件，排除历史 archive 和 artifacts 快照。直接使用点主要在共享注册和测试；默认 FeatureBuilder 按单币载入。其他家族中叫“相对强弱”的自定义实现不自动等于这个共享类。动态调用和过往运行状态不能仅凭静态搜索排除，故没有发布“全仓历史收益污染”这种结论。

实现：[相对强弱因子](../../../../src/strategy_lab/data/factors/cross_sectional.py)。[调用及版本审计](../artifacts/implementation-20260925/factor-boundary-audit.json)保存旧/新源码哈希、版本、具体反例和调用位置，含义已在本节完整说明。

## 三、账户参照能检查哪些重要错误

账户使用有正负方向的真实数量和持仓成本，不用多空互为倒数的收益公式。基本恒等式是：

`现金 = 初始现金 + 已实现盈亏 + 资金费现金流 − 成交手续费`

`权益 = 现金 + Σ[带符号数量 × (当时估值价格 − 入场均价)]`

资金费按 `−带符号数量 × 结算估值价格 × 费率` 计算。正费率时多头支付、空头收取；负费率反向。缺失的费率不等于零。成交价格已经体现的滑点不再扣第二遍。

已覆盖的关键场景：

| 场景 | 应有经济含义 |
|---|---|
| 100元卖空10份，50元买回 | 毛利润500，等于入场1000名义本金的50%，不是100% |
| 分两次买入2份@100、3份@110 | 共5份，均价106；随后卖2份@120，已实现利润28 |
| 剩余3份多头再卖5份@90 | 平掉3份后转为空头2份，空头入场价90 |
| 正常和特殊资金费 | 按各自明确事件结算；同一事件不得重复扣款 |
| 同时刻先结算再入场 | 新仓不承担在它出现之前的那次结算 |
| 止损跳空 | 穿越止损价时采用开盘成交假设，不虚构能按旧止损价成交 |
| 一根K线同时触碰止盈止损 | 合成参照采用保守止损优先；不修改旧家族原冻结规则 |
| 期末仍有持仓 | 计入未实现盈亏，不把现金直接当权益 |
| 保证金不足 | 拒绝增加风险，仍允许减仓；市场亏损本身不能被删除 |
| 重启 | 从完整事件重放检查状态；即使修改者重算了哈希，现金与事件不符仍会失败 |
| 多策略同一标的 | 合成真实净数量后记账，不同时获取虚构子账户收益 |
| 部分成交后继续交易 | 根据实际持仓重新规划，不把计划数量当已成交数量 |

保证金约束采用固定总名义敞口上限，不包含交易所阶梯维持保证金和强平。因此本工具能够判断手算经济意义和持仓预算，不能直接替代生产执行引擎。

还运行了一份固定的合成组合练习：趋势策略预算60%，对冲策略预算40%，合并为 BTC 40%、ETH 20%的净目标；经过部分成交、恢复、两笔资金费和最终平仓，从10,000合成资金得到10,186.887867。**价格是人为给定的测试数值，这不是 BTC/ETH 市场回测或收益证据。** [完整练习记录](../artifacts/implementation-20260925/synthetic-joint-account.json)保留每一步持仓、现金和事件；此处金额只用于确认接口实际连通。

工具会核对哈希链、序号和唯一记录ID，拒绝已损坏的尾行；记录追加时自动保存当前写入时间。更正要追加新记录。它能检测不一致改动，但持有文件写权限的人仍可能整体重写，因此还需要独立保留账本检查点。本轮已把账本快照纳入本地备份。

## 七、前瞻观察能落地的部分与尚未开始的部分

已完成的是记录入口和应到节点统计：数据最晚可用时间、应决策时间、实际完成及写入时间、输入/代码指纹、漏记、迟到、订单和账户证据关联。即使某个节点根本没写日志，给定固定观察时段和频率，覆盖统计也会把它算作缺失。

尚未开始的是实际持续观察。没有新开采集器、后台服务、自动化任务，也没有改变生产实例的策略和运行模式。历史回放只能写成 `backfill_diagnostic`，不能增加实时观察节点数。工具内部的及时完成标记只证明日志写入及时，仍需另核对数据当时可得、订单链完整和交易所账户一致。

实际启动观察前，需要冻结对象、输入版本、起止、决策频率和允许延迟，并接入真实采集与订单/账户来源。未来时间没有经过，就没有办法在今天“补齐一个月的连续前瞻”。本轮交付没有把这项长期工作包装成已完成。

## 八、项目研究方向应如何据此调整

本轮结果支持继续把重点放在**可信的账户增量和可保存的候选**，而不是立刻扩到更多因子或机器学习模型。现在有了更可靠的因子边界、独立算账参照、真实净额接口和已看窗口记录，下一次实验可以减少重复犯错，但盈利仍要靠后续证据。

已冻结的规则策略仍有研究价值，恢复成功说明至少这一个候选没有因证据丢失而无法核验；它不意味着极高历史收益就是未来预期。旧失败家族继续保留各自失败原因：公式错误、真实账户不盈利、输入不足和证据丢失是不同问题。
