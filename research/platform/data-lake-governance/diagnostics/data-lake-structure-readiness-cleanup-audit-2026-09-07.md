# 数据湖结构、量化适用性与冗余清理只读盘点

## 结论与范围

按用户主要研究 **15m 及以上交易机会** 的要求：目前数据湖具备可信的统一价格研究底座，足以开展分段价量统计、趋势/波动率、市场风格和条件性因子研究；还不是可直接对任意标的、任意历史区间做无偏净收益回测的完整平台。

本轮只读扫描数据湖文件元数据，对 10 个已发布数据集重新做完整 parquet 内容指纹检查，全部与其 manifest 一致；沿用与这些已验收内容对应的行质量结论，**未重新下载全历史，也未再次对全湖所有品类做 SQL 或远端质量认证**。仅新增本报告、盘点脚本和治理审计产物；未删除、移动或改写任何湖内数据。

实际盘点约 401,373 个普通文件。数据湖磁盘分配约 **18.08 GiB**，其中当前 V3 价格＋配套高周期 v2＋资金费率 v2 约 **2.99 GiB**；磁盘仍有约 **189 GiB** 可用。整个仓库约 23.97 GiB，其中研究文档/产物目录约 5.22 GiB，不应把它们与数据湖容量混为一谈。

证据：[库存汇总](../artifacts/data_lake_structure_cleanup_audit_20260907/file_inventory_summary.json)、[磁盘分配](../artifacts/data_lake_structure_cleanup_audit_20260907/allocated_usage.json)、[10 个发布版本的内容指纹检查](../artifacts/data_lake_structure_cleanup_audit_20260907/published_content_check.json)。空间使用 GiB/MiB（二进制）口径；实际删除释放量可能受 APFS 克隆、快照和文件元数据影响。

## 1. 当前组织方式

唯一结构规范为 [data-lake-spec](../../../../docs/data-lake-spec.md)，尤其第 16–18 节的版本选择与读取门禁。本表是本轮物理盘点，不建立第二套规范。

| 层 | 实际占用 | 作用 | 使用边界 |
| --- | ---: | --- | --- |
| [raw](../../../../data/raw/) | 6.30 GiB | 官方 API 原文、历史压缩档、原始价量/费率/衍生品信息 | 保留来源与重建证据，不能无条件当已接受数据 |
| [normalized](../../../../data/normalized/) | 3.70 GiB | 历史标准化 OHLCV、费率、标记价格等 | Binance 15m 是旧可信输入；legacy 1h 等不代表全市场 |
| [derived/datasets](../../../../data/derived/datasets/) | 6.62 GiB | 不可变的价格 V2/V3、高周期 v1/v2、资金费率 v1/v2 | 新研究显式锁版本，不可把全部版本一起合并读取 |
| [features](../../../../data/features/) | 0.71 GiB | 因子和部分研究特征 | 须有输入和构建来源，不能自动沿用旧特征到 V3 |
| [cache](../../../../data/cache/) | 0.72 GiB | 家族日线面板、未接受的衍生指标拼接和质量缓存 | 可重建不等于现在就可删；旧研究可能仍依赖 |
| [derived/_staging](../../../../data/derived/_staging/) | 21.55 MiB | 未完成或失败构建的暂存残留 | 未登记、不是正式输入；可列为确认后的优先清理候选 |

此外，研究结果、冻结配置、原文回执索引和验收报告在对应 `research/` 家族的 artifacts 中；这是复现证据，不是普通缓存。

价格谱系为：官方原始数据 → accepted normalized 15m v1 → 同周期刷新 V2 → 全历史缺口治理 V3 → 完整桶聚合 1h/4h/1d v2。资金费率保持独立事件链，不能先铺成每根 K 线费率再用缺失填零。

物理上仍有历史遗留：按日/按月、来源子目录和不同发布版本同时存在；旧 normalized 与家族缓存不因新 V3 发布而自动更新。因此**可以通过受控入口使用，但不是随便对 data 目录做全量文件合并也安全的结构**。

## 2. 当前统一研究输入

| 数据集 | 行数 | 观测代码数 | 最早开盘/事件 UTC | 最后开盘/事件 UTC |
| --- | ---: | ---: | --- | --- |
| 15m `history.v3` | 61,577,807 | 874 | 2019-09-08 17:45 | 2026-09-05 15:30 |
| 1h `from_15m.v2` | 15,393,559 | 874 | 2019-09-08 18:00 | 2026-09-05 14:00 |
| 4h `from_15m.v2` | 3,847,414 | 874 | 2019-09-08 20:00 | 2026-09-05 08:00 |
| 1d `from_15m.v2` | 640,378 | 874 | 2019-09-09 00:00 | 2026-09-04 00:00 |
| funding `v3_inputs.v2` | 2,654,430 | 874 | 2019-09-10 08:00 | 2026-09-05 15:00 |

以上是全数据集的最小/最大时间，不代表每个标的都有同样长的历史。15m 最后一根收盘为 **2026-09-05 15:45 UTC，即北京时间 23:45**；1h/4h/1d 最后完整收盘分别为 15:00 / 12:00 / 当日 00:00 UTC。截止尚未推进到 9 月 7 日，也不能视为持续实时更新的数据服务。

874 个历史代码的冻结元数据分类为：COIN 652、EQUITY 155、HK_EQUITY 13、KR_EQUITY 8、CN_EQUITY 2、COMMODITY 8、INDEX 3、PREMARKET 2、UNKNOWN 31。该分类来自本轮保留的元数据快照，只能做路由提示，**不是历史逐时点身份，也不是 874 个当前可交易加密币**。

币圈市场风格统计应明确加密合约范围，隔离传统资产、未知身份及零成交区间；价格趋势、市场宽度、截面离散度、相关性、波动率、成交活跃度等可在有效样本上构建。不能把当前币表回填到过去，再称为无幸存者偏差的全市场结论。

证据：[身份与零成交盘点](../artifacts/binance_v3_research_inputs_v1_20260907/identity_inventory.csv)、[V3 价格验收](binance-15m-history-v3-closeout-2026-09-06.md)、[配套高周期](binance-v3-research-inputs-v1-2026-09-07.md)、[资金费率 v2](binance-funding-v3-inputs-v2-2026-09-07.md)。

## 3. 对日常量化需求的适用性

| 需求 | 当前判断 | 必须满足的条件/缺口 |
| --- | --- | --- |
| 15m/1h/4h/1d 趋势、均线、波动率、价量统计 | 条件满足 | 显式选 V3 或高周期 v2，按连续有效段构建指标和标签 |
| 币圈市场风格、强弱轮动、截面因子诊断 | 可做观测样本研究 | 隔离非币资产；动态有效样本与缺失比例透明，不冒充完整 PIT |
| 固定标的、固定已验证窗口的净收益回测 | 条件满足 | 价格、身份、费率、成本和订单时序逐窗口通过门禁 |
| 任意标的全历史资金费用/全市场长区间净收益 | 尚不满足 | 只有 585 个标的的 639 个部分历史资金片段有原生频率证据，不是这些标的全历史通过 |
| 严格无幸存者偏差的历史选币/上市退市研究 | 尚不满足 | 历史合约身份、有效期、重命名/重开和逐时点可交易集合尚不完整 |
| 全市场 OI、基差、主动成交方向等组合研究 | 不能随价格底座自动认证 | 湖内有部分相关数据，但覆盖和接受状态须各自审计 |
| 实时决策或截至今天的信号 | 尚不满足 | 当前是固定截止快照，需另行持续增量与失败告警机制 |
| 同根 15m K 内止盈/止损先后、订单簿冲击/排队 | 粒度不够 | 可局部补更细事件数据或使用明确保守成交规则；不因此要求重下全市场 1m |

价格 V3 仍有 12 个已治理但需排除的内部边界、1,024 个原网格空位，以及 5,163,158 条原生零成交记录；它们保留用于审计，不是可直接跨越的有效交易样本。rolling、未来标签、持仓窗口都不能简单先删坏行再假装时间连续。

资金费率的事件歧义清零，解决的是“如何解释记录”，不等于“每个历史窗口费用都完整”。剩余 71 个未检索范围虽全部落在零成交价格区间，仍不能把相应费率补成零。股票额外 Special 事件也不能删除或并入普通费率。

旧 canonical 函数和被冻结的研究脚本仍可能读取 v1 或旧缓存。新研究必须显式固定 dataset ID、manifest、截止、缺口政策和标的有效性；本轮没有迁移旧研究或宣布它们重新通过门禁。

### C. 当前不应按冗余删除

- 当前 V3 价格、配套高周期 v2、资金费率 v2 和各自 manifest。
- 被输入索引引用的 raw 原文、官方 ZIP、CHECKSUM、回执和资金历史频率证据；它们与 normalized/derived 的价量重叠属于必要分层。
- 旧 accepted normalized 15m：它是旧研究和多个重建链的输入，不因为 V3 存在就成为无用副本。
- 小周期/其他市场数据：有历史家族边界，不能把“不常研究 15m 以下”解释成删除旧 1m/5m 数据的授权。
- [market_type=perp.zip](../../../../data/normalized/ohlcv/exchange=binance/market_type=perp.zip)：仅约 6.43 MiB。715 个数据成员与当前对应文件大小不同，另 715 个旧锁文件本地已不存在，并含 macOS 元数据；**不是已证实的精确重复备份**。本轮未做跨 schema 的逐行等价比较，不纳入低风险清单。详见 [压缩包核查](../artifacts/data_lake_structure_cleanup_audit_20260907/legacy_zip_comparison.json)。

## 5. 建议顺序

优先级不是扩盘或重下更细周期，而是：新研究锁定统一入口和有效标的范围 → 按实际回测窗口补齐资金结算/历史身份 → 明确固定截止后的更新方式。清理另行确认，先处理约 22 MiB 未发布残留；研究缓存只有在完成重建校验并接受复现影响后才动。

当前空间充裕，不建议为释放几 GiB 冒损失原始证据或冻结复现的风险。若以后确有容量压力，再建设可校验的冷归档/恢复路径；不能原地改动已发布版本的文件或清单。

本轮复现入口：[只读盘点脚本](../scripts/audit_data_lake_structure_cleanup.py)。它只向本轮治理 artifacts 写输出；所有容量和引用关系均为该次观察时点的证据。
