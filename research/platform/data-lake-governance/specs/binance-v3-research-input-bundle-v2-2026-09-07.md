# Binance V3 研究组合 v2：发布与启动契约

日期：2026-09-07。家族：`Binance-OHLCV-Data-Lake-Governance`。本契约在运行新校验、发布清单前冻结；规范入口为 [data-lake-spec.md](../../../../docs/data-lake-spec.md) 第 19 节。

## 范围

组合 ID 为 `binance.v3.research_inputs.v2`：15m history v3、从该 V3 完整聚合的 1h/4h/1d v2、funding v3_inputs v2。统一冻结截止为 `2026-09-05T15:45:00Z`，高周期仅到各自最后完整桶；发布日不是数据截止日。

本轮只新增组合清单、文档路由、启动检查及测试。不重建或补数，不覆盖 v1 组合，不改冻结读取器、聚合器、原费率规格，不迁移历史研究，不做冗余清理。

## 清单与检查

1. 可版本管理的固定 JSON 清单绑定五个 dataset ID、相对数据根路径、manifest SHA256、Parquet 全内容指纹、冻结截止和上下游关系；携带带来源哈希的观测分类目录。当前指针只帮助选择，新研究必须将固定清单路径、ID、SHA256 写入自己的请求，后续复现不跟随当前指针漂移。
2. `contract-only` 不访问数据湖，仅核对清单、指针及冻结读取器，结果不得表示数据已就绪。`bundle-only` 验证全部五组物理输入，仍不得表示某研究窗口通过。
3. 请求必须显式给出模式、周期、标的列表、UTC 闭合边界 `[start,end)`、缺口政策、完整回看/未来窗口长度和资产范围政策；拒绝未知字段、通配符、朴素时间、越界、错误版本和静默回退。
4. 价格必须通过 catalog 的 STRICT_CONTENT 审计，且只从返回的 verified files 读取同一请求范围；观察有效性、零成交、身份边界和时间缺口共同分段。返回逐行 `research_window_valid`，未通过的行不能用于跨段特征、标签或持仓链。
5. `price_diagnostic` 只证明观测价格窗口，不批准净收益、PIT 股票池或可交易性。`net_research` 额外要求调用方提交已复核的身份证据文件及哈希，并对每个标的整个请求区间调用 funding v2 历史日历门禁；缺失、跨段、歧义均失败，绝不补零。身份复核的真实性由研究方负责，程序只核对证据文件与时间覆盖，不伪造独立事实认证。
6. 新启动 API 返回已校验的数据与报告；CLI 只做诊断，不自动启动策略。历史 JSON 报告不是后续读取许可，实际消费者仍必须调用该 API，并纳入既有消费者登记门禁。

## 验收

须有无本地数据的契约/负向单测、实际五组全哈希验证、真实价格窗口通过、缺身份/费率日历不足时拒绝的证据；保护旧组合及冻结文件的哈希。既有不相关治理失败单独记录，不扩大白名单制造通过。

边界不升级：观测分类不等于历史身份；874 标的有费率事件不等于全历史日历；输入门禁通过不等于策略有效、可上线或新的 OOS 证据。
